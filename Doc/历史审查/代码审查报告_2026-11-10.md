# 代码审查记录（2026-11-10）

范围：当前目录内的应用层 C 源码、头文件、接入说明及测试。当前目录无 Git 历史，无法严格区分哪些函数是用户亲自新增、哪些来自此前合并；以下依据文件职责、接口及现有说明识别扩展模块。生产源码未修改，未连接或烧录硬件。

## 识别出的扩展接口

共三组、24 个公开接口，不计内部 static 辅助函数。

| 功能 | 文件 | 接口 |
| --- | --- | --- |
| 通用左右转向计算 | Robot/turn_control.c | `Turn_Left`、`Turn_Right` |
| 将转向结果写入机器人目标速度 | Robot/ax_turn.c | `AX_TURN_Left`、`AX_TURN_Right` |
| 速度斜坡初始化和配置 | Robot/ax_ramp.c | `AX_RAMP_Init`、`AX_RAMP_Config`、`AX_RAMP_SetDeadband`、`AX_RAMP_SetTimeout` |
| 速度斜坡目标和控制权 | 同上 | `AX_RAMP_To`、`AX_RAMP_Stop`、`AX_RAMP_EmergencyStop`、`AX_RAMP_Release` |
| 每周期推进和应用 | 同上 | `AX_RAMP_Update`、`AX_RAMP_Apply` |
| 速度斜坡状态查询 | 同上 | `AX_RAMP_GetSpeed`、`AX_RAMP_GetTarget`、`AX_RAMP_GetAccel`、`AX_RAMP_IsActive`、`AX_RAMP_IsSettled`、`AX_RAMP_IsStopped`、`AX_RAMP_GetCtx` |
| 按键消抖、短按和长按 | Robot/key_module.c | `key_module_scan`、`key_module_get_event` |
| 按键板级适配 | Robot/key_gpio_tarkbot.c | `gpio_get_level` |

转向参数是 m/s 和 0～100% 强度，强度不是角度，也没有转到某个角度后自动停止的功能。目前适配器仅支持 MEC/FWD。

其他主要模块：`Robot_Task` 调度底盘控制，`AX_ROBOT_Kinematics` 负责运动学与电机输出，`AX_SPEED_PidCtlA/B/C/D` 负责轮速闭环，`AX_CTL_Ps2/App/RemoteSbus` 解析遥控目标，另有灯效、显示、IMU、电量管理及 AKM 换算。这些并非根据当前证据能确认为新增的接口。

## 主要问题与修改方向

### 1. P1：任务优先级超过配置允许的范围

- `Robot/FreeRTOSConfig.h:97`：`configMAX_PRIORITIES = 5`，允许的任务优先级为 0～4。
- `Robot/main.c:53` 起：Light=5、Disp=6、Trivia=10、PS2=11。
- 同配置第 160 行启用了 `configASSERT`。这套配置和任务创建参数不一致，可能在任务创建阶段触发断言。内核源码未包含，未实测具体故障路径。
- 建议：统一优先级规划；保留现有编号时至少需要 12 个优先级，同时检查每次 `xTaskCreate` 的返回值。这应在部署前首先修复。

### 2. P1：长按恢复出厂时，先挂起控制任务，延迟三秒后才清零电机

- `Robot/ax_robot.c:585` 起：挂起 Robot/Disp → 蜂鸣器并 `vTaskDelay(3000)` → 第 594 行才写四路 PWM=0。
- 如果进入分支时车在运动，应用代码将留下原有电机指令约三秒；期间控制任务也不能继续调节。底层驱动未提供，无法验证其是否另有停止机制。
- 建议：先禁用运动并立即输出零，再挂起任务、保存参数及提示。

### 3. P1：名为 EmergencyStop 的函数只清除纵向斜坡状态

- `Robot/ax_ramp.c:159` 不立即写 `R_Vel`，也不处理横向速度、角速度、运动使能或电机 PWM；还要等 `AX_RAMP_Apply` 才写纵向目标。
- 即使执行 Apply，已有 `TG_IW` 仍保留，可能继续旋转；MEC 的零纵向目标也不能保证 PWM=0。
- 建议：把该接口明确限定为“纵向指令立即归零”，另提供统一的整车急停路径，处理全部运动分量、禁用状态及电机输出。

### 4. P1：转向和斜坡共同修改 TG_IX，直接组合会破坏限幅约束

- `Robot/ax_turn.c:75` 写前进速度，`Robot/ax_ramp.c:307` 再写一次。
- 按“转向 → 斜坡 Apply”顺序：MEC 请求 0.10m/s、100% 左转，转向计算约 0.5618rad/s；斜坡首个 20ms 周期只有 0.0012m/s。代入原运动学，内侧轮约 -0.0988m/s，与转向模块的内侧轮不反转约束冲突。实际整数接口取整会略改数值，结论相同。
- 反过来调用会由转向覆盖平滑速度。斜坡 Apply 也没有像转向适配器那样检查控制模式。
- 建议：由一个控制任务统一处理控制来源、平滑后的速度、角速度约束和最终目标写入。

### 5. P2：新增代码尚未进入当前任务调用链

- 全部实际调用检索显示：主程序没有调用 `AX_RAMP_Init/Update/Apply`、左右转向接口或 `key_module_scan/get_event`。
- `Robot/main.c:333` 创建的是原 `Key_Task`，其实现位于 `ax_robot.c:442`，直接读取 `AX_KEY_Scan`。
- `Robot/按键接入说明.md` 所说的 1ms 新事件任务和 `key_short_count/key_long_count` 在当前源文件中不存在。
- 转向说明明确注明“没有自动接入”，这本身不是转向算法缺陷；但不能把接口存在等同于车已经使用该功能。
- 建议：明确调用来源后接入；按键扫描和事件处理由同一任务负责，并统一原 PE0 功能，避免两个任务分别解释同一次按键。

### 6. P2：斜坡对实际输出的 jerk 和最大速度限制不完整

- `Robot/ax_ramp.c:244` 的收口公式没有根据当前加速度和剩余 jerk 制动需求进行规划；第 266 行强行将速度钉到目标，内部 `a_now` 因此可能与实际输出差分加速度不一致。
- 真实 C 实现离线复现：配置 `(v_max=0.4,a_max=0.6,d_max=0.9,j_max=0.1)`，目标 0.3m/s、dt=0.02s，输出差分计算的最大 jerk 约 7.099882m/s³，超过配置的 0.1。
- 同一配置先向 0.4m/s 加速 130 步，再 Stop：发出停车请求时速度约 0.340600m/s，之后峰值约 0.676000m/s，超过 `v_max=0.4`。Update 没有覆盖该场景的速度边界保护。
- 默认参数的本次基础轨迹没有复现上述大幅越界，问题出现在接口允许的其他配置与中途变更目标场景。
- `AX_RAMP_Config` 运行中还会直接截断当前速度；从 0.186m/s 降低上限到 0.1m/s 时会瞬间跳到 0.1m/s，同样不是平滑变更。
- 建议：采用能处理当前速度、加速度和目标变化的 jerk 受限规划，并明确紧急限速和正常平滑变更的优先关系。

### 7. P2：遥控无新数据或关闭 SBUS 使能开关时保留旧目标

- `Robot/ax_control.c:221` 起只在“有帧且 `sbusdata[7]<500`”时更新速度，没有对应清零分支。
- APP 同样只在收到新数据时改目标；应用层没有看到失联计时逻辑。`Robot_Task` 会继续使用保留值。
- 驱动不在本目录，不能排除其另有看门狗，但当前应用层无法保证失联停车。
- 建议：有效运动帧刷新时间戳；禁用开关立即进入停车路径，超时也由统一控制任务处理。

### 8. P2：原 PID 状态没有在停用时清除，零目标不等于零输出

- `Robot/ax_speed.c:37` 起，四轮控制器分别在 static 变量中保存累计 PWM 和上一拍误差。
- `AX_ROBOT_Stop`（`ax_kinematics.c:446`）只写电机零输出，没有重置 PID 或目标。重新使能后可能恢复旧的累计状态。
- 默认 MEC 分支没有 FWD 分支那样的零目标强制零 PWM。累计状态存在时，目标和反馈均为零也未必立即返回零 PWM。
- 建议：提供控制器重置接口，在禁用、控制权切换及重新使能时定义清晰策略；重新使能要求新有效目标。

## 其他边界问题

- **非有限参数**：`AX_RAMP_Config` 仅检查 NaN 和非正数，正无穷大被接受；`AX_RAMP_Update(NaN)` 使速度变为 NaN。Apply 在限幅前进行 float→int32 转换，对非有限值或超大值缺少保护。建议检查所有参数有限性，先限制浮点范围再转换整数。
- **超时计数回绕**：`ax_ramp.c:208` 在 uint16 存储前相加；超时设 65535ms、每步 20ms，65.54s 时计数回绕至 4，目标仍为 0.1m/s。建议更宽计数器及饱和累加。默认短超时不受这个特定回绕场景影响。
- **零死区状态错误**：允许 `SetDeadband(0)`，但 `IsSettled/IsStopped` 使用严格 `< v_min`，准确零速也返回 false。建议用独立非零判定容差。
- **AKM 校准退出仍禁用**：`ax_robot.c:568` 注释“启动”，下一行仍为 `ax_robot_move_enable=0`，所以校准退出不会恢复运动。仅影响 AKM 条件分支；默认 MEC 不进入。
- **OMT 分支参数和逆解不一致**：`ax_kinematics.c:389` 起使用 MEC 编码器速度比例；`ax_robot.h:203` 的 OMT 宏又引用 TWD 轮径。OMT 的 RT_IY 公式也不是所列逆解的逆映射：令 Fx=1、Fy=Fw=0，可得 A=-0.5、B=0.5、C=0，而 RT_IY 却为 1/3。默认 MEC 不受此分支影响。
