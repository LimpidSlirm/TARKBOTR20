# 比赛小车修正版修改说明与使用方法

本版以新加入的竞赛培训手册中的实车配置为主，沿用上传工程的按键测试用途。已经生成 ARM HEX 并完成离线测试，尚未烧录、发送运动指令或验证实车轨迹。整合前备份保留在上一级主工程的资料提取目录，本精简目录不复制备份包。当前主目录已经直接使用修正版源码。

## 实车配置与源码差异

| 项目 | 上传工程 | 修正版 | 依据 |
| --- | --- | --- | --- |
| 底盘模型 | ROBOT_MEC 麦轮 | ROBOT_FWD 四轮差速 | 培训手册适用平台、8.2、9.1 |
| 电机 | FWD 分支按 P60 电机写符号 | P30，符号独立配置 | 实拍铭牌 MC520P30-12V、培训手册 9.2 |
| 轮径 | MEC 98mm / FWD 100mm | 65mm，即 0.065m | 培训手册实车清单及 8.3 的换轮说明 |
| 编码器 | MEC 1560 / FWD 3120 计数每轮 | 122880 计数每轮，1024×30×4 | 培训手册 1.3、8.3、验收表；R20 手册第 16 页支持编码器类型差异 |
| 编码器读数 | 四路均返回 uint16，FWD 再转 int16 | 四路 int32，TIM3/TIM4 扩展溢出 | 磁编码分辨率高，旧接口可回绕并误判速度方向 |
| 反馈正负号 A/B/C/D | FWD 为 −、＋、−、＋ | ＋、−、＋、− | 培训手册 9.2 的 P30 代码 |
| PWM 正负号 A/B/C/D | FWD 为 ＋、＋、−、− | −、−、＋、＋ | 同上；与反馈符号分开配置 |
| IMU | 固定 MPU6050 | 芯片 ID 检测 MPU6050 或 QMI8658 | 旧培训资料与 V3.7 厂家例程存在版本差异 |
| V3.7 LED | PD3/PD4 | PB0/PB1 | 厂家 V3.7 基础例程 |
| V3.7 蜂鸣器 | 宏写 PE1，测试模式未初始化 | PE0 正常初始化，避免碰到 KA | 厂家 V3.7 基础例程 |
| V3.7 按键 | 测试模式 PE1/PE4 | 保留 PE1/PE4 | 对应 KA/KB |

通道保持为 A=左前、B=右前、C=左后、D=右后，主控 MA/MB/MC/MD 分别连接对应电机。

手册内部有几处不能机械照抄：

- 实车清单写 65mm，而后面的参数表仍保留 100mm，同时明确提示换成 65mm 时改为 0.065。本版采用实车清单的 65mm。
- “左快右慢左转”的文字与其逆解相反。按它的公式及 A/C 在左、B/D 在右的定义，正角速度左转应为左侧较慢、右侧较快。本版保留公式和统一符号，不照抄错误文字。
- 培训资料的 MPU6050 说明来自旧平台，不能仅凭名称断言当前芯片。新驱动读取芯片 ID 后选择对应寄存器、字节序和量程；QMI 的原生 512dps 数据归一化成原协议的 500dps 单位。
- 轮距 0.200m、滑移系数 1.75 保留为培训资料的起始值，尚未实测或做地面标定。不能把这两个数称为已标定的实车参数。

## 修改位置

### 机械参数与方向

`Robot/ax_chassis_config.h` 是比赛底盘参数入口：

```c
#define AX_COMP_WHEEL_DIAMETER_M 0.065
#define AX_COMP_ENCODER_COUNTS  122880.0
#define AX_COMP_TRACK_M         0.200
#define AX_COMP_TRACK_FACTOR    1.75
```

同一文件中的 `AX_FWD_ENCODER_SIGN_A/B/C/D` 和 `AX_FWD_MOTOR_SIGN_A/B/C/D` 分别控制反馈与驱动符号。不要靠改轮距、PID 或速度比例补偿接线/方向错误。

`Robot/ax_robot.h` 将 `ROBOT_TYPE` 改为 `ROBOT_FWD`，FWD 的四个几何/分辨率宏引用上述配置。`Robot/ax_kinematics.c` 的 FWD 分支使用 P30 符号，按实际控制周期换算速度，并对四轮目标一起缩放以维持转弯比例。

### 编码器计数

`Driver/ax_encoder.h/.c` 的 GetCounter 返回类型改为 int32_t，原初始化引脚和电机接口不变。

新增 `Driver/ax_encoder_extended.h/.c`：

- A/TIM2、C/TIM5：32 位计数范围，直接读取有符号 32 位值。
- B/TIM3、D/TIM4：16 位定时器通过更新中断累计正/负回绕。
- 在临界区读取高位、低位和待处理中断标志；处理中断尚未来得及执行时的回绕，不重复计数。
- GetCounter 接口和 FWD 调用链不再截成 int16。
- `TIM3_IRQHandler`、`TIM4_IRQHandler` 已加入固件映像。

### 控制板与 IMU

`Robot/ax_board_config.h` 的 `AX_BOARD_H60_V37=1` 是当前板级配置，使用 V3.7 的按键、LED 和蜂鸣器映射；确认使用旧 V3.2 板时可改为 0。本版没有根据培训手册中通用的 H60 名称强行认定硬件版本。

`Driver/ax_led.*`、`ax_beep.*` 和 `Robot/key_gpio_tarkbot.c` 读取该配置。V3.7 下跳过旧 `AX_SW_Init`，避免将 PB0/PB1 的 LED 引脚重新配置为输入。

`Driver/ax_mpu6050.*` 保留现有主程序调用方式，内部检测：

- QMI8658：地址 0x6A/0x6B，WHOAMI=0x05。
- MPU6050：地址 0x68/0x69，WHOAMI=0x68。
- 未找到支持的芯片或通信失败：状态变为未就绪，并禁止运动；不自动恢复起步。

新增 `Driver/ax_imu_bus.*` 提供 PB6/PB7 开漏 I2C，逐字节检查 ACK，并限制等待时间。未初始化的接收缓冲不会进入校准计算。开机/重新校准采用 32 位累计，避免 int16 累加溢出。

### 停车、控制权和任务

- `Robot/ax_speed.c/.h` 增加四轮统一的 `AX_SPEED_Reset`，保留原增量控制器的增益，改为浮点累计后限幅、再转换 PWM。
- `AX_ROBOT_Stop` 同时清除电机输出、三轴目标、轮子目标和四路 PID 历史，清零编码器采样起点。
- 按键测试动作每周期重新计算并应用目标，约 400ms 到时停车；动作中产生的按键事件被消费，不排队再次起步。
- `APP_KEY_TURN_TEST=1` 时，UART2/3 和 CAN 的接收中断只清除/取走输入，不解析控制命令；UART4、SBUS、PS2 不初始化或创建后台模式切换任务。发送遥测保留。
- Robot=4、Key=3、Trivia=2、Light/Disp=1，全部在 FreeRTOS 的 0～4 范围内。
- 机器人任务栈增加到 512 个字，启动任务增加到 256 个字；所有任务创建检查返回值。
- 控制间隔超过 40ms、传感器失败、轮速绝对值超过 0.25m/s 会锁存停机。后台校准或 EEPROM 操作挂起控制任务前先禁用并停车，避免留下 PWM。
- 原有两条 ARM 警告已修正；测试模式不编译未使用的接收解析状态变量。

本版没有加入平滑加减速模块，也没有实现循迹、视觉导航或转动到指定角度后停止的功能。

## 当前行为与调试限制

这是按键测试固件，不是完整比赛策略固件：

1. 上电先松开两个按键，等待开机流程结束。
2. 短按 KA 并松手：左转弧线；短按 KB 并松手：右转弧线；长按不触发。
3. 每次请求 0.08m/s、35% 转向强度，约 400ms 后停车。适配器向零取整，实际整数前进目标约 79mm/s。
4. 初始纵向请求上限 0.12m/s、角速度上限 0.60rad/s、单轮目标上限 0.12m/s，避免直接沿用原 1.5m/s 大速度范围。
5. 这些是软件目标限制，不是实测最高轮速、制动距离或转角精度。PID 增益、轮距与滑移仍需实车调校。

Keil Watch 可观察：

| 变量/接口 | 含义 |
| --- | --- |
| `ax_motion_fault=0` | 未触发软件故障锁存 |
| `ax_motion_fault=1` | IMU 未就绪或读取失败 |
| `ax_motion_fault=2` | 控制周期异常 |
| `ax_motion_fault=3` | 检测到超速 |
| `ax_motion_fault=4` | 任务创建失败 |
| `ax_robot_move_enable` | 运动使能；故障时为 0 |
| `ax_control_dt_s` | 实际控制间隔秒数 |
| `R_Wheel_A/B/C/D.RT` | 经过方向修正后的实测轮速 |
| `AX_MPU6050_GetKind()` | 0=未知、1=MPU6050、2=QMI8658 |

故障后应检查原因并复位，程序不会自行重新启动运动。不要为了让车动而强制把使能变量改回 1。

## 编译和烧录

工程文件为 `Project/xproject.uvprojx`，目标 `OpenCTR`，已加入新编码器扩展和 I2C 源文件。建议完整解压到短的英文路径（例如 `C:\robot\competition`），不要只复制主函数。

可用两种编译方式：

```powershell
# 本机已验证的 ARMCC 直接编译；脚本默认工具位于 C:\Keil_v5。
pwsh -File Project/build-arm.ps1
```

或者在 Keil 打开 `Project/xproject.uvprojx`，使用 ARM Compiler 5.06 update 7，执行 Rebuild。项目设置会生成 `Project/Build/competition.hex`。

直接构建脚本的固件是 **`Project/Build/competition.hex`**，与源码、日志、校验结果一起交付。本机 uVision 前端此前返回 15，没有取得前端构建结果；本版通过的是直接 ARM 工具链构建，不能把它等同于已验证 Keil GUI 一键构建/下载。

烧录时确认芯片型号 STM32F407VET6：

1. 使用 DAPLink/CMSIS-DAP 时，在 Keil 的 Debug 中选择 CMSIS-DAP；若使用其他下载器则选对应驱动。
2. 在 Flash Download 中选择 STM32F4xx 512KB Flash 算法，Flash 起始地址 0x08000000。原工程下载器设置可能仍为 ULINK2，不能直接沿用成 DAPLink。
3. 连接 SWD 和供电，选择下载后复位运行；首次将四轮架空，分别检查 KA/KB 的方向、反馈和到时停车。
4. 看四轮前进时经过符号修正的 RT 是否同为正、轮子位置是否对应 MA/MB/MC/MD。实际接线与手册不同，应先核对接线，再仅修改对应的 PWM/编码器符号。
5. 架空测试通过后，再做低速落地测试及轮距/滑移标定。本次未操作主板、未下载固件、未证明实车能按预期行驶。

不能只修改 `APP_KEY_TURN_TEST=0` 就宣称遥控或比赛模式已验收；关闭测试宏后需要另行验证控制来源、失联停车与正常模式的全流程。

## 已完成的验证

- 主机：6,277 项集成检查和 57,354 项通用转向检查通过，实际编译 FWD 运动学、转向适配、PID、IMU 核心及编码器扩展实现；硬件/RTOS 接口使用测试替身。
- 测试包含正/负编码器回绕、待处理中断读数、超过 16 位的计数、P30 反馈与 PWM 符号、左右转向、轮速限制、停止后 PID 清零、实际周期换算、MPU/QMI 字节序与量程归一化、通信失败锁存，以及从当前生产文件提取的按键状态机和 Robot_Task 延迟停车路径。
- ARM：87 个 C/汇编单元编译链接通过，0 错误、0 警告；具体映像大小和 SHA256 见 `验证结果.json`。
- HEX：逐条校验记录校验和，检查地址范围、初始栈与复位向量；在链接映像中核对 TIM3/TIM4 更新中断。
- 实车：未进行。因此机械方向、实际计数/轮、I2C 时序、电压校准、控制周期稳定性和地面轨迹仍需硬件验证。

本精简目录不附带主机测试环境；主机测试源码及入口保留在上一级整合主工程的 tests 目录。本机 Python 命令原为 Windows 占位程序，本次实际使用 Codex 随附 Python，不修改系统 Python 配置。
