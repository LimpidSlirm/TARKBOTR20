# 蓝牙重力控制与烧录记录

日期：2026-11-18，约 22:28（北京时间）。工程为当前 `Project/xproject.uvprojx`。

## 当前使用方式

1. 上电松开 KA/KB，等待启动完成。原有按键运动功能保留。
2. 使用兼容原工程 X-Protocol 的手机 APP 连接蓝牙模块。APP 发送连接指令 `0x30`、数据 `0x55` 后，蜂鸣器短鸣，控制模式变成 `APP`。仅完成手机蓝牙配对，不等于固件已经收到这条指令。
3. 选择 APP 的重力模式。前后倾斜继续控制前进/后退，左右倾斜按幅度调整左右轮差速，横移目标固定为零。
4. 小幅左右倾斜缓转，大幅左右倾斜增大轮速差。大幅转向时内侧轮目标可能反转；实际输出始终受现有单轮目标上限约束。
5. APP 接管后，按键动作不再输出电机目标；即使超时停车也保持 APP 模式，不自动恢复旧按键动作。复位后回到按键模式。

首次验证保持四轮离地，确认手机左右倾斜与预期转向一致，再做低速地面测试。手机姿态的物理方向尚未实测。没有修改蓝牙模块的名称、密码或无线配对参数。

## 配置和控制关系

`Robot/app/main.h`：

```c
#define APP_BLUETOOTH_ENABLE 1
#define APP_BLUETOOTH_TIMEOUT_MS 500u
#define APP_GRAVITY_STEER_FULL_SCALE 90
```

保留 Keil 的 `APP_KEY_TURN_TEST=1`，蓝牙使用独立开关。当前 V3.7 扩展板蓝牙连接 PA2/PA3（USART2），由 `AX_BLUETOOTH_USE_USART2=1` 选择；在启动校准结束后初始化为 115200、8N1。`AX_UART4_Init/GetData` 保留为兼容入口，实际初始化和屏蔽的是 USART2。旧 V3.2 配置仍可使用 UART4。

重力帧 `0x33` 中，`comdata[2]` 是有符号左右倾斜输入，`comdata[3]` 是前后倾斜输入。官方 APP V1.0.1 对应手册将横滚、俯仰范围定义为 ±90 度。左右输入限于 ±90 后，映射为 `目标角速度 = -左右输入 × 600 / 90`，单位为 mrad/s。实际手机安装方向和零位仍需实测。

| 左右输入绝对值 | 请求角速度绝对值 |
| --- | --- |
| 0 | 0 rad/s |
| 30 | 0.20 rad/s |
| 45 | 0.30 rad/s |
| 60 | 0.40 rad/s |
| 90 及以上 | 0.60 rad/s |

四轮差速运动学按 `左轮 = 前进速度 - 角速度 × 有效轮距 / 2`、`右轮 = 前进速度 + 角速度 × 有效轮距 / 2` 生成目标。当前 A/C 为左侧、B/D 为右侧。四轮联合限幅会同时缩小前进速度与角速度，因此表中是请求值，不是实测转弯速度。

原先 `-30 × 左右输入` 的映射在输入达到 ±20 时就碰到角速度上限，难以细调；现在整个 ±90 输入范围参与比例调节。前后输入的原有比例保持不变。

## 接管和停车

- 连接指令只在机器人控制任务中切换控制权，并先清除旧电机目标和 PID；串口中断只发布完整报文。
- APP 驾驶时需要持续发送运动帧。500ms 未收到有效摇杆、手柄或重力运动指令，控制任务清零电机输出。20ms 控制周期会带来检测延迟；实际刹停时间还取决于机械惯性。
- 灯光指令、错误校验、短帧和未知指令不会延长运动计时。若 APP 只在姿态变化时发送一次，持续倾斜也会在超时后停车，须核对 APP 的发送方式。
- 串口接收检查帧长和校验，使用独立完整帧缓冲，避免半帧读取和超出调用方 16 字节缓冲；未消费连接帧不会被随后运动帧覆盖。
- 保留 0.12m/s 单轮目标限幅、0.25m/s 实测超速锁存、方向反馈检查、IMU 故障和控制周期保护。连接或运动指令不能解除故障锁存。

## 手机连接后无反应的排查和修正

用户使用官方 APP V1.0.1，设备名称 `xtark-u8i4`，重力开关 ON 且小球移动。第一版固件已烧录并读回，但运行状态保持 ROS，UART4 没有有效帧。

对照 V3.7 控制器开发手册第 22 页的扩展接口接线，蓝牙 RX 接 PA2、TX 接 PA3，实际使用 USART2。旧工程 UART4/PC10/PC11 的映射不适用于该接口；第一版遗漏了这项板卡适配。当时 USART2 仍为 230400，且按键测试分支直接丢弃接收字节，所以手机 BLE 链路成功不等于主控收到控制指令。

第二版将蓝牙解析入口接入真实 `USART2_IRQHandler`，按 115200 配置，USART2 不再运行旧 ROS 接收分支；UART3 的 USB 通信保持原有用途。完整帧解析仍在共用的有界解析器中进行，GetData 屏蔽实际 USART2 中断防止半帧读取。增加 `ax_bluetooth_rx_bytes`、`ax_bluetooth_rx_frames`、`ax_bluetooth_last_byte` 供观察串口链路。

第二版已经重新编译、烧录、逐字节回读通过，复位后故障码 0。手机应在 APP 内断开并重连，以重新发送连接提示帧；仅切换页面不会重发连接提示。手机重连后的接管和动态重力数据另行读取确认，不能将串口寄存器初始化成功称为手机遥控已验收。

依据：本机《OpenCTR H60控制器开发手册 V1.6.0》第 22 页，以及《塔克蓝牙遥控器APP使用说明 V1.1》第 9 页。后一手册与用户的 APP V1.0.1 对应，帧号 0x33；V3.0.0 改为帧号 0x20、类型 0x03，此次不切换到 V3 协议。
