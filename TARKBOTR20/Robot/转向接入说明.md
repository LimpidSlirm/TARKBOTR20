## 已加入的文件

| 文件 | 作用 |
|---|---|
| turn_control.h/.c | 原“转向函数”目录中的通用算法原样副本，计算目标v/ω |
| ax_turn.h/.c | Robot适配，自动匹配当前运动学几何，转换为整数目标，检查控制模式及运动使能 |

完整Keil工程的Robot组需要同时包含 `turn_control.c`、`ax_turn.c`，头文件路径包含Robot目录。不要再把外部“转向函数”目录的同名.c加入同一工程，否则会重复定义。此资料包原本没有xproject.uvprojx，本轮没有捏造生产工程；已用本机匹配的完整V3.02依赖在临时工程中实际编译链接验证。

## 直接调用

在需要调用的STM32任务源文件中包含头文件：

```c
#include "ax_turn.h"

/* Call from the chosen control task with a fresh valid vision result. */
/* 0.10 m/s forward; 25 percent turning strength, not 25 degrees. */
status = AX_TURN_Left(0.10f, 25.0f);
/* Or, for a right turn: */
status = AX_TURN_Right(0.10f, 25.0f);
```

其中status先声明为 `AX_TurnStatus status;`。两行展示不同选择，实际每次只调用其中一个；在 `AX_ROBOT_Kinematics()` 前完成目标更新，不在中断中调用，不在函数内循环等待转完。

1. 速度单位m/s，强度范围0～100%，正的旋转角速度表示左转，负表示右转；强度为0表示直行，速度0不原地旋转。
2. 直接调用接口写入 `R_Vel.TG_IX`（mm/s）、`TG_IY=0`、`TG_IW`（mrad/s）；原Robot_Task仍按20ms周期运行原运动学和四轮PID，再输出PWM。适配层不直接写电机。
3. 当前只允许 `ax_control_mode == CTL_ROS`（原工程的串口/CAN外部指令模式）且原 `ax_robot_move_enable != 0` 时应用目标。不会替调用者切模式或打开运动使能。
4. 其他控制模式返回 `AX_TURN_BUSY`，保留原目标；运动禁用返回 `AX_TURN_DISABLED`，在外部指令模式下清零目标，但保持禁用状态。
5. 非法参数返回 `AX_TURN_INVALID_ARGUMENT`：在外部指令且运动使能时也会清零目标。返回OK/LIMITED才表示目标已接受；LIMITED是有效但受限的目标。其他模型返回UNSUPPORTED，原目标不变。

**零目标仅代表速度请求为零，不能代替现有运动禁用和AX_ROBOT_Stop的停车路径。** 原PID有内部状态，本轮保持原算法；紧急停止必须走原运动禁用/停车流程，不能只依赖速度0。

## 底盘与限幅

- 原默认 `ROBOT_MEC` 不变：有效轮距用 `MEC_WHEEL_BASE + MEC_ACLE_BASE`，与原麦轮在Y=0时的左右差速公式一致。支持以左右差速前进转弯，不横移。
- 原 `ROBOT_FWD` 分支：有效轮距用 `FWD_WHEEL_BASE × FWD_WB_SCALE`。切换底盘类型前仍须核对实车电机、编码器、线序与参数，未代替实车标定。
- 其他类型不自动套用上述公式。
- ax_turn.h中的初始调试上限：前进0.10m/s、旋转0.60rad/s、单轮0.20m/s，可在完整工程统一覆盖。它们是软件请求上限，不是经过落地标定的物理性能。
- 先应用通用算法限幅，再按原R_VX_LIMIT/R_VW_LIMIT和16位有符号范围限幅；向零取整，取整后复核内侧轮不反转，避免亚毫米速度被取为0而仍保留旋转。
- 目标在临界区整组写入；这避免中断看到半组数据，但**不阻止之后的串口/CAN指令覆盖目标**。视觉控制期间须由上层选择唯一外部命令来源。未修改原接收器或手柄协议，不冒称已完成视觉通信与权限仲裁。

本轮没有自动加入任何调用到Robot_Task：没有视觉数据和通信定义时不构造运动命令。调用点应由视觉接收/巡线任务在得到有效数据后触发；上面的接口已可供它调用。图像超时、丢线、平滑、重新使能策略仍由该上层任务处理。
